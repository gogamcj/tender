# 알려진 제한사항

이 문서는 단계가 진행될 때마다 갱신합니다. (최종 갱신: 3단계, 2026-10-27)

## 규칙·산식
- 낙찰하한율, 금액 구간, 복수예비가격(개수·범위·추첨) 규칙, 적격심사 배점은 아직 원문 예규와 대조해 등록한 것이 없습니다. 규칙은 사용자가 등록하며 기본 상태는 "미검증"입니다.
- 계산 엔진 테스트의 기대값은 독립 계산(분수 연산)과 수기 검산으로 만든 것입니다. 실제 공고문·공식 예시와의 교차 검증은 아직 하지 못했습니다.
- 금액 처리(절사·반올림) 규칙이 등록되지 않은 경우 원 미만 값을 그대로 표시하고 경고합니다. 임의의 법정 처리 규칙을 적용하지 않습니다.
- 부가가치세 기본 세율 10%는 계산 입력의 기본값일 뿐이며, 공고에 세액이 명시되면 명시값을 우선합니다.

## 데이터베이스
- SQLite(개발용)에서는 금액·비율을 스케일된 정수로 저장합니다. SQLite 에서 SQL 로 직접 SUM/AVG 를 하면 스케일된 값이 나오므로, 통계는 애플리케이션 계층에서 계산합니다. 운영은 PostgreSQL 을 권장합니다.
- 금액 컬럼은 정해진 소수 자릿수를 넘는 값을 저장 단계에서 거부합니다(몰래 반올림하지 않음).

## 업로드
- 열 이름 자동 추천은 정확히 일치하는 이름만 지원합니다. 나머지는 사용자가 매핑합니다.
- 한 시트에 공고 1건이 한 행인 형식만 지원합니다(병합 셀, 여러 행에 걸친 공고, 참여업체별 상세표는 아직 지원하지 않음).
- 엑셀 수식 셀은 마지막으로 저장된 계산값을 읽습니다. 저장 시 계산되지 않은 파일은 값이 비어 보일 수 있습니다.
- XLS 는 xlrd 로 읽으며, 테스트는 xlwt 로 만든 간단한 파일로만 확인했습니다.
- 사정률 이상치 경고 기준(±10%)과 낙찰률 일치 허용오차(0.001%p)는 데이터 점검용 임의 기준이며 법정 기준이 아닙니다.
- 사용자 인증이 아직 없어 업로드 작업에 업로드한 사람이 기록되지 않습니다(8단계).

## 외부 API
- 개발 환경에서 data.go.kr 접속이 차단되어 실제 API 를 한 번도 호출하지 못했습니다. 커넥터는 가짜 응답으로만 테스트했습니다.
- 오퍼레이션명·필드명 근거: 기본 URL 3개와 오퍼레이션 3개(`getBidPblancListInfoCnstwk`, `getScsbidListSttusThng`, `getDataSetOpnStdBidPblancInfo`)는 포털에서 직접 확인했고, 나머지는 공개 오픈소스 클라이언트(MIT) 구현에서 확인한 2차 근거입니다. `ntceInsttCd`, `dminsttCd`, `sucsfbidMthdNm`, `mainCnsttyNm`, `VAT`, `sucsfbidLwltRate` 는 출처를 확인하지 못한 필드명입니다. `python -m app.cli probe` 로 점검이 필요합니다.
- 응답의 낙찰률(`sucsfbidRate`)과 투찰률(`bidprcrt`)은 기준 금액이 확인되지 않아 비율 컬럼에 넣지 않고 원문만 보관합니다. 낙찰률은 확정 예정가격이 수집된 경우에만 `낙찰금액 ÷ 예정가격`으로 계산해 기준과 함께 저장합니다.
- 공고 1건에 분류번호(`bidClsfcNo`)가 여러 개인 경우(분할 발주)를 구분하지 않습니다. 같은 공고·재입찰 번호의 결과로 합쳐집니다.
- 지방자치단체 전용 API 와 계약과정통합공개서비스는 아직 조사·구현하지 않았습니다. 지자체 발주 공고는 나라장터에 게시된 범위에서만 수집됩니다.
- 공고 목록 API 는 발주기관 유형(국가/지자체)을 직접 주지 않아 비워 둡니다. 기관 코드 체계 확인 후 분류 규칙을 추가해야 합니다.
- 정기 수집 스케줄러는 내장하지 않았습니다. 명령줄 수집을 운영체제 스케줄러에 등록해 사용합니다.
